\chapter{Git e GitHub}
\label{chapter:git-e-github}
In questo capitolo vengono introdotti due strumenti fondamentali nello sviluppo software moderno: \tb{Git} e \tb{GitHub}. Essi sono ampiamente utilizzati, soprattutto nel contesto open source, dove per definizione l'intera community è invitata a contribuire attivamente ai progetti.

Sebbene spesso vengano utilizzati in modo coordinato, è importante distinguerne chiaramente i ruoli. \tb{Git è un sistema di controllo di versione distribuito, che consente di tracciare nel tempo le modifiche ai file, mantenendo una cronologia completa del progetto}. In altre parole, Git permette di effettuare il \ti{versioning}, rendendo possibile tornare a versioni precedenti, confrontare modifiche e lavorare in parallelo su diverse funzionalità. \textbf{GitHub}, invece, è una \tb{piattaforma online che consente di ospitare repository Git su un server remoto, rendendoli accessibili tramite Internet}. Questo facilita la collaborazione tra più sviluppatori, offrendo strumenti aggiuntivi come la gestione delle modifiche, il tracciamento dei problemi e la revisione del codice. Mentre le funzionalità di hosting offerte da GitHub possono essere sostituite da altri servizi simili (o anche da server privati), il ruolo di \tb{Git come sistema di versionamento rimane centrale ed è difficilmente rimpiazzabile}.

Nei paragrafi successivi verranno analizzati separatamente Git e GitHub, partendo dai concetti fondamentali fino ad arrivare al loro utilizzo combinato.


\section{Git}
\label{sec:git}
\tb{Il \ti{versioning} dei file è una pratica che permette di mantenere una cronologia delle modifiche rendendo possibile in qualsiasi momento risalire a uno stato precedente dei file}. Un modo rudimentale per ottenere questo risultato consiste nel creare copie complete dell'intero archivio ogni volta che vengono effettuate delle modifiche e conservarle per eventuali ripristini futuri. 
Sebbene questo approccio possa sembrare inizialmente funzionale, presenta diverse limitazioni, in primo luogo la dimensione dell'archivio cresce rapidamente: più i file sono grandi, più le copie richiedono spazio di archiviazione, in secondo luogo, in un contesto condiviso tra più utenti, avere molte copie indipendenti (non collegate tra loro) rende difficile tracciare le modifiche effettuate e comprendere come il progetto si sia evoluto nel tempo. Infine, anche la sincronizzazione su sistemi cloud risulta inefficiente, specialmente in presenza di archivi di grandi dimensioni.

Git nasce proprio per risolvere questi problemi, introducendo un sistema di versionamento efficiente e strutturato. A differenza dei sistemi di controllo di versione centralizzati che si basano su un server remoto per gestire e sincronizzare le modifiche tra più utenti, \tb{Git è un sistema \ti{distribuito} ovvero l'intera cronologia del progetto è salvata in locale su ogni macchina}, questo approccio offre diversi vantaggi: è possibile lavorare completamente offline sull'archivio, avendo la possibilità di consultare la cronologia, ripristinare versioni precedenti dei file e continuare lo sviluppo senza dipendere dalla connessione a Internet. Un altro aspetto fondamentale riguarda il modo in cui Git memorizza le modifiche infatti \tb{le dimensioni di un archivio Git rimangono generalmente contenute grazie a un sistema basato su \ti{istantanee} (\ti{snapshots})}. Per comprendere questo concetto, è utile fare un confronto con altri sistemi di versionamento in particolare quelli che usano un approccio basato sulle differenze dove sostanzialmente viene salvata una versione iniziale dei file e, successivamente, solo le modifiche (dette \ti{diff}) rispetto alla versione precedente. L'approccio \tb{per istantanee usato da Git prevede invece che ogni volta che viene salvata una nuova versione (commit), il sistema registra un'\ti{istantanea completa} dello stato dei file in quel momento} (per evitare sprechi di spazio, Git non duplica realmente tutti i file, se un file non è stato modificato, viene semplicemente mantenuto un riferimento alla versione già esistente). Riassunto in 2 righe, \tb{Git riesce a combinare i vantaggi di una rappresentazione completa dello stato del progetto con un utilizzo efficiente dello spazio}.

Iniziamo adesso con il vedere in modo più pratico come funziona Git e come usarlo, una cartella Git è facilmente riconoscibile grazie al fatto che al suo interno si trova la cartella \tc{.git} che di fatto è quella attraverso la quale sono effettuate le istantanee, tutti i file contenuti in essa fanno riferimento ad una particolare versione della cartella stessa e l'unico modo per ottenere informazioni su questa versione e in genere sullo storico di tutta la cartella, è avviare Git, che nel più classico dei casi si presenta con interfaccia a riga di comando.
